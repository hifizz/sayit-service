# SayIt v0.1 — 项目约束与已确定决策

## 目标

把音频转换成用户本来就想发送的文字。以 Typeless 的公开可观察行为对齐最终效果：去口癖、意图不变的语法修整、局部改口、技术词纠正、适度结构化，以及从真实用户编辑中获得个性化。客户端不是研发重点，首个适配场景是 ThreadChat `ai_prompt`。

## 范围

实现 Grok Voice Transcribe 2.0 batch 适配、可替换 JSON LLM、rewrite/guard/一次修复/原文回退、个人及项目词典、原子反馈学习、抽象展示风格、PostgreSQL、鉴权与用户隔离、数据删除/过期、测试与可重复评测。直接文本接口用于诊断 ASR 以后的链路。

不实现 macOS/Windows 客户端、自动读其他应用、LoRA、复杂 agent、支付计费和通用实时流式服务。其他 context type 是接口扩展槽；v0.1 调优和验收集中在 ai_prompt。

## 对此前口头方案的安全细化

1. “用户改一次就立即全局学习”改为：明确大小写/空格规范及显式确认可立即生效；不确定的同音替换成为候选，至少来自两次独立口述的同一替换证据才可生效。这是待真实数据校准的工程阈值，不是已标定概率。
2. 不再把 `hedging: low` 作为可执行风格。直接、简洁不等于更确定。任何可能/考虑/需验证都属于语义，不可被风格删除。
3. 最终整条 ThreadChat 消息不等于本次口述片段。必须追踪片段范围，多次口述分别反馈；无法确认范围则跳过学习。
4. 语义检查不是形式化证明。自动化 guard 失败要回退，真实有效性仍由人工评测验证。
5. 不为实现“记住”依赖对话记忆；仓库中的 Spec、AGENTS 与版本化提示词才是后续研发事实源。

## 阶段与验收

v0.1 工程验收：可启动服务；离线无 Key 测试；真实 PostgreSQL 事务和数据隔离；真实 provider 适配代码；音频与模型 Key 到位后能运行同一条链路及评测命令。

v0.1 质量验收：提供有代表性的真实中文/中英混合口述、人工逐字参考、期望发送文字，以及同输入 Typeless 输出。对比语义、编辑成本、术语、改口、回退和延迟。在此之前不称“已对齐 Typeless”。

后续按数据推进：校准词典阈值、改进真实难例、明确目标模型与延迟预算，然后再考虑 streaming、持久任务队列与多副本分布式限额。不因为工程通过就自动启用微调。
